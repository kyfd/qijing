# 架构说明

本文描述“文件生态系统 Agent”的**目标架构与设计保证**。项目处于早期开发阶段；文中组件、边界和控制措施不应被理解为均已实现或已经验证。实际能力以当前代码、测试和发布说明为准。

## 架构目标

系统面向 Windows 本地环境，围绕四条原则设计：

1. **授权优先**：没有初始扫描权限，只观察用户逐个加入白名单的根目录。
2. **能力最小化**：扫描进程只具备遍历、元数据读取及用户可选的本地哈希能力，完全不实现任何修改授权目录文件的接口。唯一的文件处置能力位于主进程，只能在用户逐项确认后把文件移入 Windows 回收站，永不永久删除、移动或改写。
3. **本地优先**：索引、规则分析、摘要和界面默认全部在本机完成，网络默认关闭。
4. **数据分层**：扫描器处理文件系统事实，规则引擎处理结构化索引，Agent 只接触匿名聚合数据。

### 主进程

目标职责包括：

- 保存白名单根目录和每个根的扫描策略；
- 启动、取消和限制扫描任务；
- 把扫描结果写入应用自己的数据库；
- 运行确定性分类规则，生成解释与建议；
- 提供仅绑定 `127.0.0.1` 的本地页面和 API；
- 生成离线中文摘要；
- 对可选 Agent payload 做匿名化、预览和审计；
- 调用 Windows Explorer 的“显示并选中”能力。

主进程对应用私有数据目录有写入需求，但目标上不对授权目录执行写操作。

### scanner 子进程

scanner 以独立进程 `qijing-scanner.exe` 运行，以缩小扫描能力边界：

- 仅接受主进程传入的、已经规范化的白名单根和扫描选项；
- 遍历目录并读取允许的元数据；
- 默认不打开文件正文；
- 仅当用户对该根开启本地哈希时读取文件字节并在本地计算摘要；
- 跳过或拒绝越过授权根的 symlink、junction 和其他 reparse point；
- 不包含删除、移动、重命名、覆盖、截断、创建或修改授权目录文件的业务 API；扫描器进程保持零写能力，回收站操作不经过它；
- 通过版本化的 Named Pipe IPC 返回结果；管道 DACL 只允许当前用户连接；不向 Agent 或网络直接发送数据。

进程分离本身不是安全证明。设计仍需配合最小权限、路径校验、句柄打开方式和不变性测试。

### 可选托盘与浏览器

托盘目标上只提供打开界面、开始扫描、暂停观察和退出等入口。浏览器界面调用本地 loopback API；它不直接访问文件系统。界面中的文件相关动作仅限于请求应用在资源管理器中定位目标。

## 数据流

### 1. 授权

1. 初始白名单为空。
2. 用户逐个添加根目录，并选择元数据扫描、敏感排除和是否允许本地哈希。
3. 主进程规范化路径并保存到应用配置。
4. 后续扫描只能引用处于启用状态的白名单根。

### 2. 扫描

1. 主进程构造最小扫描任务并交给 scanner。
2. scanner 对根目录进行边界校验，拒绝路径逃逸。
3. scanner 读取文件名与路径以完成遍历和归属判断，并采集允许的元数据；这些定位信息只用于本地扫描和索引，不进入 Agent payload。
4. 默认情况下不读取文件内容。
5. 若用户开启本地哈希，scanner 读取符合规则的文件字节，在本地计算哈希，只返回摘要；原始字节不持久化、不发送。
6. 主进程把扫描结果、错误和范围写入应用私有数据库及审计记录。

### 3. 分析与展示

1. 规则引擎读取索引与历史快照。
2. 引擎计算活动度、增长、重复候选和其他启发式分类。
3. 本地摘要器基于规则结果生成说明。
4. 本地 API 按视图需要返回聚合数据和节点详情。
5. 用户可忽略或延后建议，也可在 Explorer 中定位文件；系统不执行文件处置。

### 4. 可选 Agent

1. Agent 适配层从规则结果中选取允许字段。
2. 真实路径、文件名、正文、内容片段、哈希和用户身份信息在发送前排除。
3. 路径相关实体替换为本地生成的匿名 ID，数值按需要分桶或聚合。
4. 用户查看将要发送的确切 payload，并显式开启联网能力。
5. 请求和响应摘要进入本地审计记录。
6. 模型输出只用于解释和摘要，不能扩大授权，也不能触发文件操作。

## 信任边界

| 边界 | 受信内容 | 不应授予的能力 |
| --- | --- | --- |
| 用户 ↔ 本地界面 | 用户操作、白名单选择 | 隐式全盘授权、文件处置 |
| 主进程 ↔ scanner | 规范化根、扫描策略、结构化结果 | 任意路径访问、写文件命令 |
| scanner ↔ 文件系统 | 白名单内只读元数据；可选哈希读取 | 删除、移动、重命名、写入、回收站 |
| 主进程 ↔ 回收站 | 用户逐项确认过的、位于授权根内的常规文件 | 永久删除、清空回收站、未确认的批量操作 |
| 主进程 ↔ 数据库 | 应用配置、索引、审计 | 把应用数据写入授权目录 |
| 本地界面 ↔ loopback API | 带令牌的同源请求 | 外部网页无凭据调用 |
| Agent 适配器 ↔ 外部模型 | 经预览的匿名聚合 payload | 真实路径、正文、权限决策 |

## 威胁模型

### 保护资产

- 授权目录中文件的内容、名称、路径、时间戳和目录结构；
- 用户未授权目录及系统目录；
- 应用私有数据库中的本地索引和扫描历史；
- 可选模型凭据、请求 payload 和审计记录；
- 本地服务控制扫描和授权状态的能力。

### 主要威胁与目标缓解措施

#### 路径逃逸与重解析点

**威胁**：白名单内的 symlink、junction 或 reparse point 指向未授权位置；大小写、UNC、短路径或 `..` 导致边界判断错误。

**目标控制**：使用 Windows 语义规范化绝对路径；按路径组件做包含关系判断；检测并默认拒绝重解析点跨根；扫描前后再次验证最终目标；测试大小写、UNC、保留名和边界前缀。

#### 扫描器意外修改文件

**威胁**：错误的打开标志、库函数副作用或未来功能扩张改变文件内容、名称、位置或时间戳。

**目标控制**：扫描器中不实现文件修改接口；按只读方式打开；扫描业务层禁止删除、移动、重命名和创建；在测试中比较扫描前后的目录树、大小、内容哈希与时间戳。应用对授权目录的设计保证是永不永久删除、移动、重命名或改写内容。

#### 回收功能被滥用或越权

**威胁**：路径遍历、符号链接或重解析点逃逸导致授权根之外的文件被回收；确认令牌重放；预览与执行之间文件被替换（TOCTOU）；批量操作规模失控。

**目标控制**：候选仅限 rotten / orphan 分类，单批上限 50；两阶段 preview → confirm，令牌一次性、10 分钟过期、以常量时间比较；选择指纹绑定快照 ID 与每个文件的路径、大小、修改时间；预览与执行两次执行路径校验（授权根包含、拒绝根本身与整盘根、拒绝符号链接与重解析点、必须是常规文件）；执行时重新打开文件并比对完整 Windows 文件身份（卷序列号 + 文件引用号 + 大小 + 时间戳，见 [ADR 0003](adr/0003-windows-file-identity.md)），不符即拒绝；使用 `FOF_ALLOWUNDO` 保证可还原，保留 `FOF_WANTNUKEWARNING` 以免超大文件被静默永久删除；每项结果写入独立于快照的审计表。

#### 敏感内容泄露

**威胁**：扫描密钥、钱包、浏览器资料、环境变量、证书或源码秘密；真实路径或文件名通过日志和模型 payload 泄露。

**目标控制**：白名单初始为空；默认敏感排除；默认只读元数据；本地哈希需逐根显式开启；日志最小化；Agent 字段 allowlist；发送前 payload 预览和本地审计；默认禁止网络。

#### 本地 Web 服务被其他网页调用

**威胁**：恶意网站向 loopback API 发请求，发起扫描、读取本地信息或更改授权配置。

**目标控制**：只监听 `127.0.0.1`；随机会话令牌；严格 Origin/Host 校验；限制 CORS；改变状态的请求使用防伪机制；不暴露文件修改端点。

#### 模型输出越权或提示注入

**威胁**：外部模型响应或文件名中的恶意文本诱导系统访问更多路径、联网或修改文件。

**目标控制**：模型不接触正文和真实路径；输出视为不可信文本；模型只解释既有规则结果；权限和扫描范围由本地确定性代码控制；不存在从模型文本映射到文件修改操作的执行器。

#### 数据库或配置损坏

**威胁**：崩溃、恶意本地进程或损坏数据造成错误结论和越界扫描。

**目标控制**：事务写入、版本化迁移、配置校验、扫描时重新校验白名单，不依据数据库中的任意路径跳过边界检查。应用无法防御已完全控制当前 Windows 用户账户的恶意软件。

#### 资源耗尽

**威胁**：超大目录、循环、海量小文件或哈希大文件导致 CPU、内存和磁盘 I/O 过载。

**目标控制**：并发和预算限制、取消、分批结果、循环检测、可选分层哈希、默认跳过云端占位文件，并提供明确进度和错误分类。

## 明确的非保证

- 目标架构不能替代实现审计；在对应代码和测试完成前，不应声称隔离措施已经验证。
- 本应用不能防御拥有相同或更高 OS 权限的恶意本地进程。
- “未备份”“重复”“腐烂”“僵尸”等是启发式标签，不构成删除或恢复建议。
- 本地哈希能够比较已读取内容，但不会证明外部副本、云端状态或备份可恢复性。
- Explorer 定位会把控制权交还给用户和 Windows；用户随后执行的操作不属于应用行为。

## 验证计划

设计保证应由以下测试持续支撑：

- 路径规范化与 reparse point 逃逸测试；
- 未授权根、敏感排除和云端占位文件测试；
- 扫描前后目录树、内容哈希、大小、名称和时间戳不变性测试；
- 默认网络关闭及 Agent 字段 allowlist 测试；
- loopback API 的 Origin、令牌和状态变更请求测试；
- Windows 临时目录上的端到端扫描测试，不使用开发者真实文件。
