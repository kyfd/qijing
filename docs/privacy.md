# 隐私说明

本文定义“文件生态系统 Agent”的目标数据边界和隐私设计保证。项目处于早期开发阶段，相关控制措施仍需通过实现、测试和发布审计验证。

## 核心承诺

- 应用只扫描用户**明确加入白名单**的目录，初始白名单为空。
- 对授权目录中的文件和目录，未经用户逐项确认，应用永不触碰；唯一可能的写操作是把用户已确认的文件移入 Windows 回收站，永远可还原。
- 应用永不永久删除、移动、重命名或改写授权目录中的任何文件。
- 默认扫描只访问元数据，不读取文件正文。
- 只有用户为某个授权根显式开启“本地哈希”时，扫描器才读取文件字节；计算在本地完成，原始字节不保存、不上传。
- 默认不联网、无遥测、无需云端模型。
- Agent 只允许接收匿名标识和聚合特征；真实路径、文件名、正文和内容摘要不得进入 Agent payload。
- 撤销授权或清理索引只影响应用私有数据，不触碰源文件。

## 数据分类与字段

以下字段是目标数据模型。实际版本可能只实现其中一部分。

### 授权配置

保存在应用私有数据目录，用于确定扫描边界：

| 字段 | 用途 | 是否进入 Agent payload |
| --- | --- | --- |
| 授权根真实路径 | 确定白名单边界 | 否 |
| 根目录启用状态 | 控制是否扫描 | 否 |
| 元数据扫描选项 | 控制采集范围 | 否 |
| 本地哈希开关 | 控制是否允许读取文件字节 | 否 |
| 排除规则 | 跳过敏感或无关位置 | 否 |
| 扫描预算与计划 | 控制资源使用 | 否 |

### 本地扫描索引

扫描器为完成遍历需要看到路径和文件名；它们只用于本地边界判断、索引和界面定位，不应离开设备。

| 字段 | 目标用途 | 说明 |
| --- | --- | --- |
| 所属授权根 | 边界与聚合 | 本地保存 |
| 相对路径、文件名 | 建立目录关系、搜索、Explorer 定位 | 敏感；禁止进入 Agent payload |
| 文件/目录类型 | 分类和统计 | 可匿名聚合 |
| 扩展名或类型类别 | 类型统计 | Agent 侧优先使用泛化类别 |
| 文件大小、目录聚合大小 | 空间与增长分析 | Agent 侧可分桶或聚合 |
| 创建、修改、最近观测时间 | 活动度分析 | Agent 侧转换为年龄区间或闲置天数 |
| 文件系统身份或本地节点 ID | 快照关联 | 不直接发送；使用新的匿名 ID |
| 属性标志 | 判断隐藏、系统、占位或 reparse point | 仅本地使用或匿名布尔值 |
| 扫描错误类别 | 可观测性 | 排除路径和错误正文后可聚合 |
| 内容哈希 | 用户开启本地哈希后做重复检测 | 仅本地；禁止进入 Agent payload |
| Git 只读状态摘要 | 启发式项目状态 | 不发送分支名、提交信息或远端 URL |

应用不以收集正文为目标，不应保存文件字节、内容片段、文档文本、图片像素、音视频内容或归档内文件内容。

### 应用运行与审计数据

目标上可能保存：

- 扫描开始和结束时间、持续时长、状态和计数；
- 已应用的排除规则与跳过原因；
- 分类结果、解释、忽略和稍后处理状态；
- 匿名 Agent 请求 payload、目标服务标识、时间、结果状态及必要的响应摘要；
- 本地服务错误，但应清除正文、凭据和不必要的绝对路径。

这些数据位于应用私有数据目录，不写入用户授权目录。

**数据目录位置**：应用私有数据固定放在 `%LocalAppData%\Qijing\`
（`data`、`logs`、`cache`、`backups`、`updates`），并把目录 DACL 明确限制到
当前用户、SYSTEM 和 Administrators（受保护 DACL，不继承宽泛授权）。
扫描索引包含真实路径与文件名，按其敏感级别**不得**放在可能随漫游配置
文件复制的 `%AppData%` 中。从旧版本升级时，应用执行一次性迁移：
完整性检查 → 迁移前备份 → 临时目录复制 → 再次检查 → 原子切换 → 写完成
标记；旧目录保留不删，任何一步失败都保持原状。细节与失败模式见
[ADR 0001](adr/0001-localappdata-data-dir.md)，迁移逻辑由
`internal/appdir` 的测试覆盖。

## 白名单授权模型

1. 首次启动没有任何授权根。
2. 用户可逐个选择目录；“扫描整台电脑”也必须先展示并再次确认确切的本地固定磁盘列表，不存在隐式全盘授权。
3. 整机入口默认不包含 U 盘、光驱、网络映射盘或离线磁盘。
4. 扫描任务只能引用启用中的白名单根。
5. 路径须规范化，并拒绝通过 symlink、junction 或 reparse point 越过根边界。
6. 整机扫描默认关闭正文读取与哈希，跳过云端占位文件，并受到条目、错误与持续时间预算约束；达到预算只保存标记为部分结果的本地快照。
7. 移除根授权后，后续扫描不得再访问该目录；用户可清除其本地索引，源目录保持不变。

授权某个父目录意味着扫描器可能观察其未排除的后代。通常应优先授权范围尽可能小的目录；只有确实需要全局视图时才使用经过范围预览和确认的整机入口。

## 默认敏感排除

目标默认规则应跳过常见秘密、身份资料、系统位置和高噪声缓存，包括但不限于：

- SSH 与 GnuPG：`.ssh`、`.gnupg`；
- 环境和凭据文件：`.env`、`.env.*`、常见 credentials/secrets 文件；
- 私钥、证书与密钥库：如 `.pem`、`.key`、`.pfx`、`.p12`、`.kdbx`；
- 加密货币钱包和恢复材料目录；
- 浏览器用户资料、Cookie、登录数据和会话存储；
- Windows 系统目录、回收站和系统卷信息；
- Git 对象数据库及敏感配置，例如 `.git/objects`；
- 依赖与构建缓存，例如 `node_modules`、包缓存和大规模生成目录；
- 隐藏目录、云端占位文件，以及无法安全判定边界的 reparse point。

排除规则是纵深防御，不是扩大授权的依据。即使用户缩减排除项，扫描器仍不得越出白名单，也不得获得写能力。规则的精确集合与大小写、通配符和 Windows 路径语义需由测试验证。

## 本地哈希

本地哈希默认关闭，并按授权根显式开启。

开启后：

- scanner 可以只读方式打开符合白名单和排除规则的文件；
- 读取的字节仅在内存中用于计算本地摘要；
- 原始字节不写入数据库、不加入日志、不发送给 Agent；
- 哈希值仅存于本地，用于精确重复候选和快照关联；
- 可使用大小门槛、预算和分层策略限制 I/O；界面应明确这种策略可能产生“候选”而非确定结论；
- 用户关闭本地哈希后，未来扫描不再读取文件字节；本地既有哈希的清理策略应在界面中明确提供。

哈希本身也可能是敏感指纹，因此不允许进入外部 Agent payload。

## Agent 匿名 payload

### 字段 allowlist

目标 payload 只允许使用完成解释所需的最小字段，例如：

```json
{
  "schema_version": 1,
  "region_id": "region_7f2c",
  "category": "dormant_project",
  "file_type_mix": {
    "source_code": 0.62,
    "documents": 0.21,
    "other": 0.17
  },
  "size_bucket": "1-5 GiB",
  "idle_days_bucket": "180-365",
  "growth_bucket": "stable",
  "duplicate_candidate_count": 3,
  "rule_reasons": ["long_inactive", "structured_directory"]
}
```

这是设计示例，不代表当前版本已有网络请求能力或采用完全相同的 schema。

### 明确禁止字段

以下数据不得进入 Agent payload：

- 绝对路径、相对路径、目录名和文件名；
- Windows 用户名、设备名、卷序列号和稳定设备标识；
- 文件正文、内容片段、图片或其他原始字节；
- 内容哈希、Git commit hash、分支名、提交信息和远端 URL；
- 环境变量、API 密钥、模型密钥、凭据和 Cookie；
- 精确的创建/修改时间（应转换为年龄或区间）；
- 足以重新识别个人项目的自由文本标签；
- 未经 allowlist 明确许可的新字段。

匿名 ID 应为应用本地生成、不可由真实路径直接反推的标识；对外请求可按会话或请求轮换，避免跨请求长期关联。

### 网络控制

- 默认网络关闭，离线规则摘要应能独立使用。
- 用户必须显式配置并开启兼容模型。
- 发送前应展示确切的脱敏 payload、目标服务和时间。
- payload 与请求结果进入本地审计；审计不得反向加入被排除的敏感字段。
- 模型响应仅作解释文本，不授予新目录权限，也不能触发文件操作。
- 关闭网络后，不应发生模型请求、遥测、更新检查或其他后台上传；如未来加入任何联网功能，必须单独披露和选择加入。

## 文件处置边界

对授权目录，产品设计保证是：

- 不永久删除文件或目录；
- 不移动文件或目录到用户未指定的位置；
- 不重命名文件或目录；
- 不创建、覆盖、追加、截断或修改文件内容；
- 不改写归档、不自动解压；
- 不执行 Git checkout、commit、clean、reset 或其他写操作；
- 不修改文件属性、ACL、时间戳或替代数据流；
- 不向 Agent、CLI 或模型暴露任何文件处置接口。

唯一的例外是「整理与回收」：用户在界面上逐项勾选、再经过一次独立确认之后，主进程会调用 Windows Shell 的 `SHFileOperationW`（带 `FOF_ALLOWUNDO`）把这些文件移入回收站。它不清空回收站，也不绕过回收站直接删除；文件过大无法进入回收站时会中止而不是永久删除。

关于该功能的进一步约束：

- 只有被判为 rotten 或 orphan 的文件才可能成为候选；大文件和休眠文件永不进入候选。
- 单次回收上限 50 个文件；确认令牌一次性、10 分钟过期。
- 预览与执行两个阶段都会重新校验路径必须位于授权根内、不得是根本身或整盘根、不得经过符号链接或重解析点、必须是常规文件。
- 若文件在预览之后大小或修改时间发生变化，本次确认自动失效。
- 扫描器进程本身完全不具备写能力；回收只在主进程中执行。
- 每次回收都写入本机审计记录（`recycled_items`），该记录独立于扫描快照存在，快照被删除后仍然保留。

“在资源管理器中显示”只打开 Windows Explorer 并选中目标，后续操作完全由用户决定。

应用会写入自己的配置、数据库、日志和审计数据。这些写入必须位于应用私有数据目录，而不是用户授权扫描目录。用户主动执行“撤销授权”“删除索引”或“重置应用数据”时，只删除应用自己的记录。

## 数据保留与用户控制

目标上，隐私界面应允许用户：

- 查看当前授权根及每个根的本地哈希状态；
- 查看默认和自定义排除项；
- 查看最近扫描范围、跳过项和错误类别；
- 查看网络开关、模型目标及最近实际 payload；
- 撤销根授权并删除对应本地索引；
- 导出隐私与审计数据；
- 重置应用私有数据，并在执行前明确将删除的对象。

实现这些能力前，不应宣称当前构建已经提供完整导出或清理功能。卸载或删除应用数据不会删除任何源文件；已经被移入回收站的文件仍然留在 Windows 回收站里，可以正常还原。

## 已知边界

- 文件名和路径本身可能敏感；本地界面展示它们是实现搜索与定位所需，但它们不应联网。
- 元数据也可能泄露行为模式，因此索引应按本地敏感数据保护。
- 已完全控制当前 Windows 用户账户的恶意软件可能读取应用数据库或操纵进程，本应用不能构成该场景下的安全边界。
- 排除规则无法涵盖所有自定义秘密位置；用户应只授权完成目标所需的最小目录。
- 本地哈希会读取字节并产生磁盘 I/O；如果不需要精确重复检测，应保持关闭。
